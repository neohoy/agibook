# 01 · 工位凭什么不一样

<div class="ab-def">

同一个模型，装在不同的壳里，能干的事天差地别。差别不在模型，在**这个壳给了它多少手脚**：能不能读你的文件、能不能改、能不能跑命令、记不记得这个项目。

</div>

## 三种形态

| | 便签纸 | 工位 | 车间 |
| --- | --- | --- | --- |
| **形态** | 网页 / App 聊天框 | 桌面 Agent 工具 | 编码 IDE |
| **典型用途** | 问问题、改文字、整理材料 | 处理你电脑上的一批文件、跑一件多步的活 | 写代码、改工程 |
| **读你的文件** | ✗ 你贴进去 | ✓ | ✓ |
| **改你的文件** | ✗ | ✓ | ✓ |
| **跑命令 / 跑代码** | ✗ | 多数可以 | ✓ |
| **项目上下文** | 无 | 有（项目 / 空间的概念） | 有（整个代码库） |
| **规矩存在哪** | 你每次贴 | 项目里的规则文件 | 项目里的规则文件 |
| **风险** | 低 | **中到高** | **高** |

三档不是"越往右越好"，是**越往右手脚越多、风险也越大**。

## 桌面工具真正改变的四件事

### 一、它认得你的项目

聊天框里，你每次都要重新交代背景（[入门篇 04 章](../start/04-context)讲过：它没有记忆）。桌面工具里，"这个项目是什么、有哪些文件、上次做到哪儿"是它自己能看到的。

**这一条省掉的是你重复交代背景的时间**，而背景恰恰是[五要素里最多人跳过的一格](../prompt/)。

### 二、规矩可以写成文件，自动生效

多数桌面工具支持在项目根目录放一个**规则文件**（各家名字不同）。打开这个项目，里面写的规矩自动生效。

这就是 [System Prompt](../start/07-system-prompt) 的项目版：**不用每次贴，也不会被人改歪。**

::: tip 这里正好把三个东西串起来
- **规则文件** = 项目级的 System Prompt，每次都生效，放通用偏好
- **[Skill](../skill/)** = 按需触发的能力包，放某一类活的完整做法
- **[提示词](../prompt/)** = 这一次的具体任务

三层，从常驻到临时。桌面工具的价值之一，就是把前两层从"你记着贴"变成"它自己读"。
:::

### 三、它能真的动手

这是最大的一条。聊天框里它只能"告诉你该怎么做"，桌面工具里它可以**直接做**：批量改文件、跑脚本、装依赖、提交代码。

也正是从这里开始，[Agent 篇](../agent/)那套东西从理论变成日常：

| Agent 篇讲的 | 在桌面工具里长什么样 |
| --- | --- |
| [给它手：工具](../agent/03-tools) | 它自带一套（读文件、写文件、跑命令、搜网页） |
| [MCP](../agent/04-mcp) | 多数桌面工具支持配 MCP Server，接你自己的系统 |
| [划边界](../agent/05-boundaries) | 目录白名单、权限档位、确认弹窗 |
| [设上限](../agent/06-limits) | 步数 / 时长 / 额度上限 |
| [看得见](../agent/08-observe) | 运行记录、改了哪些文件的 diff |

**你在 Agent 篇学的东西，在这里全都有对应的开关。**

### 四、能力可以被打包和共享

Skill、规则文件、MCP 配置——这些都是文件，可以提交到仓库、可以发给同事、可以有版本。

**这一条决定了它是"你的技巧"还是"团队的资产"**（[Skill 篇 02 章](../skill/02-when)）。

## 那我该待在哪一档

<div class="ab-do">

**按你的活来定，不是按工具的先进程度：**

| 你的活 | 待在哪一档 |
| --- | --- |
| 问问题、改文案、整理一段材料、写周报 | **便签纸就够**。别折腾 |
| 每次都要处理你电脑上的一批文件 | **工位** |
| 一件活要跑好几步，你在复制粘贴中间结果 | **工位**（顺便看 [Workflow 篇](../workflow/)） |
| 写代码、改工程 | **车间** |
| 需要接内部系统 | 工位或车间 + [MCP](../agent/04-mcp) |

**大多数非技术岗的人，一直待在前两档就够了。** 别因为"编码 IDE 看起来更专业"就往那边跑——你不写代码，那些能力对你是负担不是收益。

</div>

## 一个常见的误判

::: warning "换个更强的工具，效果就上去了"
不会。工具决定的是**它能碰到什么**，不是**它做得好不好**。

你在聊天框里写不清楚的需求，搬到桌面工具里还是写不清楚——**只是现在它会带着这份含糊，去动你的真文件**。

所以顺序是：**先在便签纸上把方法练熟，再换工位。** 这跟 [Skill 篇](../skill/02-when)那条"提示词还没调稳就别打包"是同一个道理。
:::
