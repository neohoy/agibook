# 工具篇 · 工位

[入门篇 09 章](../start/09-map)埋过一个比喻，这一篇是它的兑现：

> 那 Claude Code、Codex、WorkBuddy 这些算什么？
> **它们是你安排新人干活的"工位"。** 同一个新人，你让他在一张便签纸上办公（网页聊天框），还是给他一个配齐了文件、工具、流程的工位，产出是不一样的。

[模型篇](../models/)讲的是"人"——哪些模型、各自什么脾气。这一篇讲"工位"——**同一个模型装进不同的壳里，能干的事差别有多大**。

::: warning 这一篇和模型篇一样会过期
写法也一样：**不写版本号、不写价格、不排名**，只写**这东西是什么、解决谁的问题、官方入口在哪**。每个都给了链接，具体情况你自己去看。

内容截至 **2026 年 9 月**。与官网不一致时以官网为准。
:::

## 为什么只讲有桌面版的

通用工具这一块，本篇**只收有桌面版的**。这不是偷懒，是一条有意义的分界线：

| | 网页聊天框 | 桌面工具 |
| --- | --- | --- |
| 能不能读你的文件 | 不能，只能你贴进去 | **能**，直接读目录 |
| 能不能改你的文件 | 不能 | **能** |
| 能不能跑命令 / 跑代码 | 不能 | **能**（多数） |
| 有没有项目上下文 | 每次从零 | **有**，认得这个项目 |
| 规矩存在哪 | 你自己记着贴 | **项目里的规则文件**，自动生效 |

**这一列差别，就是"便签纸"和"工位"的实质。** 网页聊天框那类到处都是，也不太需要挑——真正会改变你工作方式的，是能碰到你本地东西的那些。

::: tip 权限大了，规矩就得跟上
桌面工具能动你的文件、能跑命令，这既是它的价值，也是它的风险。

**[Agent 篇 05 章](../agent/05-boundaries)那套边界，从这里开始就不是纸上谈兵了**——沙箱、目录白名单、危险动作必须人点头，用桌面工具时全都用得上。这一篇的 [04 章](./04-choose)会再提一次。
:::

## 配套手册

这一篇给的是**地图**——每个工具两三百字，够你判断该不该装。真要上手用某一个，本站作者另外写了几本单独的手册，一本讲一个：

| 手册 | 讲什么 |
| --- | --- |
| [Claude Code 中文教程](https://claudebook-e38.pages.dev/) | 官方文档重新编排的学习路径，简 / 繁 / 英三语 |
| [Codex 中文手册](https://neohoy.github.io/codexbook/) | 从装上 CLI 到交给 CI，外加官方中文文档镜像 |
| [豆包工作手册](https://neohoy.github.io/doubaobook/) | 界面、技能、连接器、云电脑与飞书打通 |
| [WorkBuddy 手册](https://neohoy.github.io/workbuddybook/) | 三种工作模式、权限沙箱、技能与连接器，12 个实战案例 |
| [OpenDesign 手册](https://neohoy.github.io/opendesignbook/) | 安装、接本地 Agent、设计系统，主线是十步做一份可编辑 AI PPT |

::: tip 这几本和这本书的分工
**这本书讲方法**（[五要素](../prompt/)、[Skill](../skill/)、[Workflow](../workflow/)、[Agent 的边界](../agent/)）——换到哪个工具上都成立。

**那几本讲某一个工具怎么用**——菜单在哪、开关什么意思、这个工具特有的坑。

所以正确顺序是：**先在这里学方法，需要上手某个具体工具时再去翻对应那本。** 反过来会变成学了一堆快捷键，但还是不会把需求说清楚。

它们都是非官方的社区教程，产品功能以各家官方最新说明为准。
:::

## 一句话先给你

> **工具决定你能干什么，方法决定你干得好不好。**

这本书前面五篇讲的全是方法——[五要素](../prompt/)、[Skill](../skill/)、[Workflow](../workflow/)、[Agent 的边界](../agent/)。**那些东西换到哪个工具上都成立。**

所以这一篇的正确读法是：**看看有哪些工位，挑一个，然后回去把方法练熟。** 别在选工具上花超过一个下午——[入门篇 10 章](../start/10-choose-and-rules)那条建议在这里同样有效：

> 入门期就用一个网页聊天框，别折腾工具。是因为遇到了具体的墙才去换工具，不是因为看了篇文章说某个工具牛。
