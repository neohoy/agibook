# 03 · 专用工具

<div class="ab-def">

上一章那些是通用工位。这一章是**专用车间**——只干一类活，但把那一类干到底。理解它们的关键是一句话：**专用工具卖的不是更强的模型，是一条已经封装好的 [Workflow](../workflow/)。**

</div>

## 先说清楚它们的本质

拿 AI 做一条短片，你自己搭的话是这样：

```text
写剧本 → 拆分镜 → 定角色形象 → 逐镜生成视频 → 配音 → 配乐 → 剪辑成片
```

七步，每步都要选模型、调提示词、验收、接管子——这是一条标准的 [Workflow](../workflow/)，而且是条难搭的。

**专用工具做的事，就是把这条线整个封装好卖给你。** 你只管给一个想法，它内部跑完这七步。

::: tip 这解释了两件事
**一、为什么它们值钱。** 它们省掉的不是"生成"那一下，是**串联、角色一致性、格式转换、返工**这些脏活。

**二、为什么它们不灵活。** 封装好的流水线，你只能改它开放出来的那几个旋钮。要完全自己控制，就得回去自己搭。

**这跟 [Workflow 篇 09 章](../workflow/09-tools)那个"手动串 / 编排工具 / 代码"的取舍是同一件事**——专用工具是别人替你做好的编排。
:::

## 音乐 · Suno

**是什么**：文字生成音乐。给一段描述（风格、情绪、乐器）或者一段歌词，出一首带人声的完整歌。

**能用在哪**：视频配乐、播客片头、活动主题曲、产品演示的背景音。

**用它时注意**：

- **描述要具体到"可听"**——"欢快的歌"和"民谣吉他扫弦，中速，男声，副歌加合唱"，差的是信息量。这还是[提示词篇](../prompt/05-format)那条"把形容词换成结构"。
- **商用授权看清楚**。这一类工具的授权条款跟你的套餐挂钩，用在对外内容前先确认。

**入口**：[suno.com](https://suno.com/)

::: tip 同一档的其他方向
**ElevenLabs**（[elevenlabs.io](https://elevenlabs.io/)）做的是语音——配音、朗读、声音克隆，跟 Suno 的音乐是两回事。做有声内容时这两类经常一起用。国内 MiniMax、讯飞在语音这块也有产品（见[模型篇 02](../models/02-china)）。
:::

## 数字人 · HeyGen

**是什么**：数字人视频。选一个形象（或者用你自己的），输入文案，出一段"有人在镜头前讲话"的视频。支持多语言口型对齐。

**能用在哪**：产品介绍、培训课程、多语言版本的宣传片、社媒口播——**凡是"需要一个人对着镜头讲一段"的场景**。

**它省掉的是什么**：真人出镜的排期、场地、重录。改一句文案不用重拍，重新生成就行——**这一条是它最实际的价值**。

**用它时注意**：

::: warning 数字人有一条明确的红线
**用别人的形象和声音做数字人，必须拿到本人授权。** 未经授权地生成"某个真人在说某段话"的视频，在多数地方都是违法的，跟工具好不好用没关系。

用你自己的形象、或者工具提供的虚拟形象，才是安全的用法。
:::

**入口**：[heygen.com](https://www.heygen.com/)

## AI 短剧 / 视频 · Flova、LibTV

这一类是上面说的"封装 Workflow"的最典型代表。

### Flova

**是什么**：一站式的 AI 视频 / 短剧创作平台。你给一个故事或剧本，它内部由**多个分工的 Agent**（编剧、分镜、视觉等）接力，走完剧本 → 角色与场景 → 分镜 → 视频 → 配音配乐 → 剪辑成片的全流程。

**特点**：

- **聚合多家视频模型**——不锁死在一个模型上，不同镜头可以用不同的；
- **角色一致性**是它主打的点（同一个角色在不同镜头里不"崩脸"）——这是 AI 视频里最难也最关键的一环；
- 语音和音乐环节接了外部能力（如 ElevenLabs、Suno 那一类）。

**入口**：[flova.ai](https://flova.ai/)

### LibTV

**是什么**：同方向的另一个，定位偏"专业视频创作工具"。

**特点**：同样**聚合多家视频模型**，另外有一套"导演台"式的精细控制——3D 虚拟场景、逐帧参考，让你能对画面下更细的指令，而不只是给一段描述。

**入口**：[liblib.tv](https://www.liblib.tv/)（旧域名 libtv.ai 会跳转到这里）

<div class="ab-do">

**这一类工具怎么判断好不好用，看两个地方，别看它宣传的模型有多强：**

**一、角色 / 风格一致性。** 十个镜头里同一个人长得像不像同一个人——这是这类工具的真正难点，也是最容易翻车的地方。

**二、返工成本。** 第七个镜头不满意，能不能只重做那一个？还是整条要重跑？**这直接决定你用它是省时间还是费时间**——道理跟 [Workflow 篇 04 章](../workflow/04-handoff)那条"每一步的产出要能单独重跑"完全一样。

</div>

::: tip 国内还有一批
剪映 / 即梦（字节）这一类，从视频剪辑侧长出 AI 能力，跟上面这些从生成侧长出来的路径不同，但目标市场重叠。做视频的话值得都试一遍——这个方向变化极快，本书不做取舍。
:::

## 前端设计 · OpenDesign

**是什么**：**开源**（Apache-2.0）的本地优先设计工具，桌面应用。它自己不训练模型也不托管你的东西——**它接你已经装在电脑上的 Agent**（Claude Code、Codex、Cursor、OpenCode 那些），提供中间那一层：设计系统、需求表单、预览沙箱、导出管线。

**能产出什么**：落地页和网页、App 原型、可编辑的 PPT（能导出 PPTX）、海报和配图、数据看板、设计系统，以及代码驱动的动效视频。

**特点**：

- **产物是你仓库里的真文件**，不是别人数据库里的一条记录——能 diff、能回滚、能交给工程接着写；
- **BYOK**，用你自己的 key 或者直接指向你本机的 CLI，数据不过第三方；
- 换 AI 工具的成本低——设计系统和技能都是 Markdown，能带走。

**给谁**：要经常出视觉产物、但不想被托管型设计工具锁住模型和数据的人。接客户项目、或者在内网环境干活的，这两条是硬需求。

**入口**：[open-design.ai](https://open-design.ai/)

**深入**：[OpenDesign 手册](https://neohoy.github.io/opendesignbook/)（本站作者写的非官方手册，主线是十步做出一份可编辑的 AI PPT）

::: tip 注意它和上一章那些工具的关系
OpenDesign 不是"另一个 Agent"，**它是给你已有 Agent 加的一层**。所以它和 [02 章](./02-general)那些工具不是二选一，是叠加。

这也是"专用工具"的另一种形态：**不重新造一个模型或 Agent，只把某个垂直领域的流程和规范封装好。**
:::

## 一条通用的判断

<div class="ab-do">

**要不要用专用工具，问一句：这条流水线我自己搭，划算吗？**

- **偶尔做一次** → 用专用工具。自己搭的时间成本收不回来。
- **每天都做，而且对细节有要求** → 先用专用工具跑通，摸清楚这条线由哪几步组成，**再判断要不要自己搭**（[Workflow 篇](../workflow/)）。
- **要嵌进自己的产品** → 多半得自己搭，或者用它们的 API。

**别一上来就自己搭。** 专用工具最大的价值，是让你用几十块钱和一个下午，看清楚这条流水线到底长什么样。

</div>
