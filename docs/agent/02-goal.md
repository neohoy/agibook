# 02 · 给目标：自主度越高，目标越要写死

<div class="ab-def">

Workflow 里你写的是**步骤**，Agent 里你写的是**目标**。听起来轻松了，其实反过来——**步骤你可以中途改，目标一旦发出去就没人管了**。所以目标要写得比任何一条提示词都硬。

</div>

## 一份目标书的四块

一个能用的目标，不是一句话，是四块：

```text
① 目标      要拿到什么
② 完成标准  什么情况算做完   ← 最多人漏的一块
③ 边界      不许做什么
④ 交付形态  最后交给我的东西长什么样
```

对照一下：

```text
❌ "帮我调研一下这几家竞品的定价。"

✅ 目标：查清 A / B / C 三家的定价方案，用于我们下周的定价会。

   完成标准：三家各拿到「套餐名 + 价格 + 计费单位 + 包含什么」四项。
   任一项在官网公开信息里找不到，就标注「未公开」并附上你查过的页面——
   不要去猜，也不要用第三方博客的转述。

   边界：
   - 只看这三家的官网和官方文档，不看第三方评测和社区讨论；
   - 不要注册账号、不要提交任何表单；
   - 不要联系对方。

   交付：一张表，四列，每行一个套餐。表下面列出「未公开」的项和你查过的地址。
```

第二个版本长了十倍，但它把 Agent 最容易跑偏的三处都堵死了：**查到什么程度算够、可以去哪儿、交出来什么样。**

## ② 完成标准：最该花力气的一块

不写完成标准，会出现两种极端，而且都很常见：

**一种是永远不完。** 它转了十五圈，每圈都在"再确认一下""再补充一点"，因为没有任何东西告诉它"够了"。

**另一种是草草交差。** 第二圈它就说"我已经找到了主要信息"——因为也没有任何东西告诉它"还不够"。

<div class="ab-do">

写完成标准的方法：**写成一份它能自己对照的清单**，而不是一个形容词。

```text
❌ 完成标准：调研得比较充分。
✅ 完成标准：以下每一项都有结果（找到了，或明确标注"未公开"）：
   □ A 家：套餐名 / 价格 / 计费单位 / 包含内容
   □ B 家：同上
   □ C 家：同上
   全部有结果即完成，不要再继续查。
```

最后那句"**全部有结果即完成，不要再继续查**"，是防止它无限扩展的最有效一句话。

</div>

## ①③④ 各自的写法

### ① 目标：加上"为了什么"

```text
❌ 查清三家的定价。
✅ 查清三家的定价，用于我们下周的定价会——
   我们要判断自己的价格带位置，所以最关心「起步价」和「计费单位」。
```

**用途会影响它的每一次判断。** 知道你要比价格带，它遇到一个复杂的阶梯定价时，会知道该抓哪一档；不知道，它就随便抓一个。

### ③ 边界：写成能执行的动作，不是原则

```text
❌ 注意信息来源要可靠。
✅ 只看这三家的官网和官方文档；第三方评测、社区讨论、AI 生成的对比文章一律不采信。
```

边界这块 [05 章](./05-boundaries)单独展开，那里讲的是"权限层面"的边界。这里说的是"任务层面"的：**别去哪儿、别用什么、别做什么动作。**

### ④ 交付形态：连中间产物一起规定

Agent 交出来的不只是最终结果，还有它的过程。两样都要规定：

```text
交付：
1. 一张表（四列：套餐 / 价格 / 计费单位 / 包含内容）
2. 表下面：「未公开」项的清单，每项附上你实际查过的 URL
3. 最后：你的查证路径（每家你打开了哪几个页面）——一行一条，不要展开描述
```

第 3 条就是[后面要讲的"留痕"](./08-observe)，**在目标里就要求它交，比事后去日志里翻方便得多**。

## 三个具体的写法技巧

### 一、把"不知道"变成合法的结果

Agent 最危险的时刻，是它查不到但又必须往下走的时候——**它会编**。

所以要给"查不到"一个出口，跟[提示词篇 06 章](../prompt/06-constraints)那条"每个禁止配一个出路"是同一招：

```text
任何一项在官方来源里找不到，就在表里填「未公开」，并在清单里注明你查过哪些地方。
「未公开」是一个合格的结果，不扣分。**猜一个数字才扣分。**
```

最后那句是点睛——**明确告诉它"承认查不到不算失败"**，它才敢承认。

### 二、给出停止条件，不止是完成条件

完成条件说的是"什么算成功"，停止条件说的是"什么情况下不要再试了"：

```text
遇到以下情况，停下来告诉我，不要自己想办法绕过：
- 页面需要登录或注册；
- 需要提交表单才能看到价格；
- 连续三次尝试都拿不到某一项。
```

**不写这一条，它会"想办法"** ——而它想的办法可能是去第三方站点找、可能是根据同类产品推算、也可能是编一个。

### 三、如果有偏好路径，就说出来

Agent 不需要你规定步骤，但**如果你知道怎么做最快，说出来能省很多圈**：

```text
建议路径（不强制，你可以调整）：
先找官网的 pricing 页面；没有的话找文档站的 billing 章节；
再没有就看官方博客的发布公告。
```

写"不强制"很重要——**写死了它就成了 Workflow，那你不如直接写 Workflow。**

## 一份目标模板

```text
# 目标
【要拿到什么】，用于【干什么】——所以我最关心【哪一点】。

# 完成标准
以下每一项都有结果（拿到，或明确标注"未获得"）：
□ 【项 1】
□ 【项 2】
全部有结果即完成，不要继续扩展范围。

# 边界
- 只能【可以做的】
- 不要【明确禁止的动作，一条一行】
- 遇到【这些情况】就停下来问我，不要自己绕过

# 交付
1. 【最终产物的结构】
2. 未获得项的清单，每项附上你实际尝试过的来源
3. 你的执行路径（一行一步，不要展开）

# 说明
"未获得"是合格结果。猜一个答案才是不合格。
```

## 一个检验方法

<div class="ab-do">

把你写的目标发给一个同事，问他两个问题：

1. **"你觉得干到什么程度算完？"**
2. **"如果你查不到其中一项，你会怎么办？"**

两个问题他都答得上来、而且答案跟你想的一样——目标就写清楚了。

答不上来，Agent 也答不上来。区别只是**同事会来问你，Agent 不会**。

</div>
