# 10 · 从玩具到能用

一个 Agent 在你自己电脑上跑通，和它能真的接进日常工作，中间还差一段。这一章讲那一段。

## 大多数 Agent 死在哪儿

不是"跑不出结果"，是**没人敢用**。

它能干活，但没人知道它会干出什么，于是每次都得有人全程盯着。全程盯着的 Agent，还不如一条 [Workflow](../workflow/)——至少 Workflow 不用盯。

所以"能用"的标准不是效果，是：**你敢不敢在不盯着的情况下让它跑。**

前面九章讲的边界、上限、留痕、验收，全都是为这一句服务的。

## 上线的四个阶段

别一步到位。按这个顺序走，每一阶段待到你有把握了再往下：

### 阶段 1 · 陪跑

你在旁边看着它跑，每一圈都看。目的不是防它出错，是**建立体感**：它一般跑几圈、在哪儿容易卡、工具够不够用。

跑五到十次。这个阶段你会改最多东西——主要是[工具描述](./03-tools)和[目标](./02-goal)。

### 阶段 2 · 跑完就验

不盯过程了，但每次跑完都按[上一章](./09-accept)那四分钟验一遍。

这个阶段要建[测试集](./09-accept)，尤其是"不该做什么"那几个用例。

**跑到测试集连着三轮全绿，再往下。**

### 阶段 3 · 挑不重要的活先上

给它真实的活，但挑**错了也不要紧**的：内部参考材料、初稿、不对外的整理工作。

这个阶段的目的是撞上你在测试集里想不到的情况——**真实材料的脏乱程度，永远超过你编的用例。**

### 阶段 4 · 接进日常

到这一步，人工闸只保留在**对外和不可逆**的动作上（[05 章](./05-boundaries)），其余放开。

::: warning 每一阶段的退回条件
任何阶段出现这三种情况，退回上一阶段：

- 它做了一件你完全没预料到的事；
- 交付物里出现了编造的事实；
- 连续两次撞上限。

**退回不丢人，硬着头皮往前才丢人。**
:::

## 关于多智能体

你会刷到"多个 Agent 协作"的说法：一个查资料、一个写、一个审。

::: warning 单个 Agent 都没调稳之前，不要碰
多智能体把这一篇所有的问题都乘以了 N：
- 上下文管理从一份变成 N 份；
- 出错定位从"哪一圈"变成"哪个 Agent 的哪一圈"；
- 成本从不可预估变成更不可预估；
- 一个 Agent 的错误结论会被另一个当成事实接受。

**先把一个 Agent 跑到能不盯着用，再谈第二个。**
:::

真的需要多个的时候，**优先用 [Workflow](../workflow/) 把它们串起来**，而不是让它们自由协商：

```text
❌ 三个 Agent 在一个群里互相讨论，自行决定谁做什么
✅ Workflow：① 调研 Agent → ② 人工确认 → ③ 撰写 Agent → ④ 人工确认
```

右边这个有明确的交接点、明确的中间产物、明确的验收——**它的每一条好处，都来自"是 Workflow 而不是自由协作"。**

## 上线前清单

**目标**

- [ ] 目标写清了"为了什么用"
- [ ] 完成标准是一份可勾选的清单
- [ ] 明确写了"未获得也是合格结果，猜一个才不合格"
- [ ] 写了停止条件（遇到什么情况停下来问，而不是自己绕）
- [ ] 写了"不要扩展范围，想到的建议列在最后"

**工具**

- [ ] 每个工具的描述写了"做什么"和"什么时候用"
- [ ] 一个工具一件事（没有 action 参数那种大杂烩）
- [ ] 工具返回精简且带来源，长内容落文件只回摘要
- [ ] 错误信息告诉它下一步该怎么办
- [ ] 高风险动作**没有给工具**，或者只产出待确认的计划

**边界**

- [ ] 文件读写范围限定到具体目录，输出到独立目录
- [ ] 凭据是最小权限的（不是管理员 key）
- [ ] 联网：不联网 / 白名单 / 说清风险，三选一
- [ ] 要执行命令的，在沙箱里
- [ ] 对外、删除、花钱：一律人工确认

**上限**

- [ ] 步数上限，且撞上限时交部分结果 + 缺口 + 路径
- [ ] 重复检测（连续三次同样尝试无果就换路）
- [ ] 成本或时间上限
- [ ] 并发上限（如果有并发）

**看得见**

- [ ] 有系统日志，**含工具返回内容**
- [ ] 目标里要求它交执行报告（一行一步）
- [ ] 关键结论要求附依据

**验收**

- [ ] 测试集有 A 能力 / B 诚实 / C 边界 / D 停止四类用例
- [ ] 每个用例跑过三次
- [ ] 有一个四分钟的验收流程，并且真的在做

## 这一篇的收口

十章可以压成三句：

> **能力靠模型，工具和边界靠你。** 一个 Agent 表现不好，先查工具描述，最后才怀疑模型。
>
> **能靠"不给"解决的，别靠"说服"解决。** 跑三十圈之后，只有硬约束还站得住。
>
> **没有依据的输出，验收成本高到不值得用。** 让它交依据，比让它更聪明重要。

## 然后呢

你现在走完了五步：

| | 你会了什么 |
| --- | --- |
| [入门篇](../start/) | 它是什么、为什么会忘会编、怎么把一件事说清楚 |
| [提示词篇](../prompt/) | 让一条提示词稳定、可验收、能交接 |
| [Skill 篇](../skill/) | 把跑通的一步打包，一次写好、反复触发 |
| [Workflow 篇](../workflow/) | 把几步串成能重复跑、每步能验收的流水线 |
| **Agent 篇** | 写不出步骤的那一步，怎么放手而不撒手 |

这条路到这儿基本完整了。**从"把一句话说清楚"到"让一个东西替你跑完一整件事"，中间没有魔法，只有一层层把不确定性收回来的手艺。**

最后一句，跟这本书[开头那句](../start/)是同一句：

> **先搞懂它是个什么东西，技巧就不用背了。**

现在你大概能理解为什么了——**这五篇里没有一条是"记住这么写就对了"，每一条都能推回到"它只是在预测下一个字"。**
