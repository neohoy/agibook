# Skill 篇 · 从每次重讲，到一次写好

你在[提示词篇](../prompt/)调出了一条很好用的提示词。然后你发现一件烦人的事：

> **下次干同样的活，你还得把这一大段重贴一遍。**

而且同事拿去用，改着改着就成了另一个版本。三个月后，团队里流传着四条互相矛盾的"标准纪要提示词"，没人知道哪条是对的。

**Skill 就是这个问题的解**：把一套规矩打包存起来，以后一句话触发，人人用的都是同一版。

## 一句话说清它和前面的关系

| | 是什么 | 存在哪 | 生效范围 |
| --- | --- | --- | --- |
| **Prompt** | 这次交代的话 | 你的聊天框里 | 这一次 |
| **System Prompt** | 入职约法三章 | 这个对话 / 这个项目的设置里 | 这段对话的每一轮 |
| **Skill** | 一本 SOP 手册 | 一个文件（夹），可以给别人 | **被触发时**，跨对话、跨人、跨项目 |

关键区别在最后一格：**Skill 是按需触发的**。你装十个 Skill，平时它们都不占地方；说到相关的活，对应那个才被读进来。这一点决定了它的全部设计，[03 章](./03-anatomy)细讲。

## 判断标准，先给你

> **一件事你只干一次，Prompt 就够；一件事你每周都干，就值得做成 Skill。**

不确定的时候看 [02 章](./02-when) 那张表。**做早了是浪费，做晚了是重复劳动**，这一章帮你卡住那个点。
