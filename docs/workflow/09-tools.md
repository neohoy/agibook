# 09 · 用什么串

<div class="ab-def">

三种串法：**手动串**、**编排工具串**、**代码串**。这一章不横评产品——产品名和界面下个月就变。**讲的是三种串法各自的成本曲线，以及你什么时候该从这一档换到下一档。**

</div>

## 三种串法

| | 手动串 | 编排工具 | 代码 |
| --- | --- | --- | --- |
| 怎么干 | 聊天框里一步步跑，复制粘贴 | 拖节点连线，或填表单配置 | 自己写脚本调 API |
| 搭起来 | 零成本 | 半天到几天 | 几天起 |
| 改一步 | 改提示词就行 | 改一个节点 | 改代码，可能要测 |
| 分支、循环、重试 | 靠你自己记得 | 内置 | 想怎么写就怎么写 |
| 接外部系统 | 不行 | 看它支持哪些 | 都行 |
| 出错定位 | 你眼睛看着 | 看它的运行日志 | 看你自己打的日志 |
| 谁能维护 | 你 | 会用这个工具的人 | 会写代码的人 |
| 适合频率 | 一天几次以内 | 一天几十次 | 更高，或要嵌进产品 |

## 手动串：别急着离开这一档

**大多数人低估了手动串能撑多久。**

四步流水线，一天跑两三次，手动跑一次十分钟。一个月六十次、十小时。而搭一套自动化，从选工具到调通，通常也要几天——**还要持续维护**。

::: tip 手动串不是"还没自动化"，是一个合法的终点
一条一天跑两次、每次都要人看的流水线，自动化省不下多少，反而多一个会坏的东西。

判断标准：**你花在"复制粘贴和等待"上的时间，有没有超过花在"判断"上的时间。** 没超过，就先别自动化。
:::

手动串的三个提效办法，成本都接近零：

**一、把每一步做成 [Skill](../skill/)。** 不用每次重贴提示词，一句话触发。这是投入产出比最高的一步。

**二、把流水线定义表存在手边。** [03 章](./03-decompose)那张表，打印出来或者钉在文档顶上。**照着表跑就不会漏步。**

**三、固定一个存中间产物的地方。** 一个文档，四个小节，对应四步。跑到第三步发现不对，回第二步的小节改，不用重头来。

## 编排工具：多数团队的落点

界面化的流程编排产品（拖节点连线那类，也包括各家 AI 平台里的"工作流"功能），特点是**不用写代码就能把步骤、判断、循环、重试配出来**。

**什么时候换到这一档：**

- 一天要跑十次以上，复制粘贴的时间明显超过判断的时间；
- 需要定时触发（每天早上自动跑）；
- 需要接一两个外部系统（读表格、发消息）；
- 要给不写代码的同事用。

**换过来要付的代价：**

- **学这个工具本身。** 它的节点怎么连、变量怎么传、错误怎么处理，都是新知识。
- **调试变间接了。** 手动跑时你直接看见每一步的输出；在工具里得去翻运行记录。
- **被工具的能力框住。** 它没有的节点类型，你就得绕。
- **多一个会坏的东西。** 工具升级、接口变更、账号过期，都会让你的流水线某天早上不跑了。

<div class="ab-do">

选编排工具时，别看功能列表，看这四件事：

1. **能不能看到每一步的完整输入输出？** 看不到就没法调试，这是第一硬指标。
2. **失败之后能不能从中间某步重跑？** 不能的话每次调试都要从头，又慢又贵。
3. **人工审批这一环好不好用？** [07 章](./07-human-in-the-loop)那道闸，多数流水线撤不掉。
4. **提示词能不能方便地改和版本管理？** 提示词是你要改最多的东西。埋在界面深处、改了没记录，早晚出事。

功能多不多是次要的。**这四条决定你三个月后是在用它，还是在骂它。**

</div>

## 代码：什么时候才值得

**换到这一档的信号只有两个：**

- 编排工具的表达能力不够了（复杂分支、动态步骤、要跟自有系统深度集成）；
- 这条流水线要变成产品的一部分，给用户用，而不只是内部跑。

除此之外的"想自己写更灵活"，通常是低估了维护成本。

::: warning 写代码不会让流水线更准
前面八章讲的东西——拆步骤、中间产物、验收闸、重试策略、人工卡点——**换成代码写，一条都不能省**。

代码解决的是"怎么串"，不是"串得对不对"。**一条设计得差的流水线，写成代码只是错得更快。**
:::

## 一个混合做法

实践中最常见、也最省事的形态是**混合**：

```text
① 整理纪要      ← Skill，你在聊天框里触发
② 抽待办        ← Skill
②' 核对         ← Skill
③ 生成消息      ← Skill
④ 人工确认      ← 你
⑤ 发出去        ← 你自己发，或者用一个简单脚本
```

**四个 Skill + 一张流程表 + 你自己。** 没有任何编排工具，但每一步都固化了、不会漏步、每步都能单独重跑。

这个形态覆盖了相当多的真实场景，而且**从这里升级到编排工具很平滑**——步骤和提示词都是现成的，只是换个地方跑。

## 换档的时机

```text
手动串
  ↓  复制粘贴的时间 > 判断的时间；或者需要定时跑
编排工具
  ↓  工具表达不了；或者要变成产品的一部分
代码
```

**每一档都待够久再往下走。** 跳档的代价是：你还没把流水线跑顺，就先背上了一个工具的维护成本。

## 一件跟工具无关但很重要的事

不管用哪一档，**流水线定义表要有一个人类可读的版本**（[03 章](./03-decompose)那张）。

工具里的配置是给机器看的。半年后有人问"这条线到底干了啥"，你需要一张四行的表，而不是一张连了二十个节点的图。

**这张表也是交接文档、是排错时的对照物、是你自己三个月后的记忆。**
