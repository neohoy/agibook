# 02 · 什么时候该串起来

<div class="ab-def">

判断标准和 [Skill 篇](../skill/02-when)那条是一脉的，只是往上走了一层：**一件事只有一步，做成 Skill 就够；一件事有好几步、而且每次都是同样几步，才值得串成流水线。**

</div>

## 四个"该串了"的信号

### 信号 1：你在复制粘贴中间结果

最直接的信号。第一步跑完，你复制输出，开个新对话，粘贴，再跑第二步——**这个"复制粘贴"的动作，就是流水线里缺的那根管子**。

一天做三次以上，就该串了。

### 信号 2：你老是忘了做某一步

"哎，这次忘了按责任人分组。" 步骤在你脑子里，就一定会漏。**写下来的流程不会漏。**

### 信号 3：这套流程你要教给别人

口头交代"你先这样、再那样"，对方回去执行成什么样是随机的。**一条写下来的流水线，本身就是最好的交接文档。**

### 信号 4：出了问题你说不清是哪一步的锅

结果不对，你只知道"最后出来的东西不行"，但不知道是纪要抽错了、还是分组分错了、还是消息模板不对。

**这说明你现在的做法没有中间检查点**——串起来之后就有了，见 [05 章](./05-checkpoints)。

## 三种不该串的情况

### 一、每一步还不稳

**这是最重要的一条。** 串联会把不稳定乘起来：

| 每步的合格率 | 三步串完 | 五步串完 |
| --- | --- | --- |
| 95% | 86% | 77% |
| 90% | 73% | 59% |
| 80% | 51% | 33% |

（这只是个直观的算法，实际情况没这么线性——但方向是对的：**越往后越差，而且差得比你以为的快**。）

所以顺序不能反：**先把每一步单独调到测试集全绿（[提示词篇 08](../prompt/08-iterate)），再串。**

### 二、每次的步骤都不一样

如果这次是三步、下次是五步、顺序还可能变——那它就不是流水线。硬做出来的会是一堆 if-else，比不做还难维护。

**判断方法**：把你过去三次做这件事的过程写下来，对比。步骤对不上，就先别串。

::: tip 但先别急着结论说"那我需要 Agent"
更常见的情况是：**大部分步骤是固定的，只有一两步需要看情况。**

那就把固定的部分串成流水线，把"看情况"那一两步留给人（[07 章](./07-human-in-the-loop)）或者留给 Agent（[10 章](./10-when-agent)）。**不要因为一步不确定，就把整条线都交出去。**
:::

### 三、一个月才跑一次

跟 Skill 一样的道理：搭流水线有成本，跑得太少收不回来。**存一份步骤清单，手动照着做。**

## 一个判断顺序

按这个顺序问自己，答案自然就出来了：

```text
1. 这件事是一步还是多步？
   一步  → 用 Prompt；每周都干就做成 Skill。到此为止。
   多步  ↓

2. 每次都是同样这几步吗？
   不是  → 先别串。想想是不是有几步其实是固定的。
   是    ↓

3. 每一步单独跑，稳吗？
   不稳  → 回去调那一步。串联会把问题放大。
   稳    ↓

4. 我一周跑几次？
   一两次以下 → 存一份步骤清单，手动跑。
   更多       → 串起来。
```

## 值得串的几类活

给你几个真实的例子找感觉——它们的共同点是**步骤固定、每步产出明确、有一个天然的人工卡点**：

| 流水线 | 步骤 |
| --- | --- |
| **会议 → 派活** | 纪要 → 抽待办 → 按人分组 → 生成消息 →（人过一遍）→ 发 |
| **需求 → PRD** | 原型描述 → PRD 初稿 → 自查缺口 →（产品确认）→ 定稿 |
| **周报汇总** | 各人流水 → 分别规范化 → 合并去重 → 按项目分组 → 生成汇总 |
| **客户来信 → 回复** | 分类（咨询/投诉/需求）→ 按类型走不同模板 → 起草 →（人审）→ 发 |
| **长文 → 内容包** | 通读做地图 → 分段提炼 → 合成摘要 → 生成要点卡片 |
| **面试 → 评估** | 记录整理 → 按维度打分 → 汇总成评估表 →（面试官确认）→ 归档 |

注意每一条里都有一个**（人）**。这不是保守，[07 章](./07-human-in-the-loop)会讲为什么它几乎总是该有。

<div class="ab-do">

现在挑一件你手上真实的多步活，做两件事：

1. 把步骤写在纸上，一步一行；
2. 在每一步后面写清楚：**这一步的产出是什么样子的**。

第 2 件事写不出来的那一步，就是拆得不对——[下一章](./03-decompose)讲怎么拆。

</div>
