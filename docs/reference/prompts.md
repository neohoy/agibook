# 提示词模板库

全书用到的提示词集中在这一页，**整段复制，把方括号里的内容换成你的**。

每条都遵守同一个骨架：[角色 / 任务 / 背景 / 要求 / 验收](../start/06-prompt)。看多几条你会发现它们长得几乎一样——**这正是重点**。

::: tip 想知道这些模板为什么这么写
[提示词篇](../prompt/)拆解了背后的每一条：为什么把材料放最后、为什么每个"不要"都跟着一句"那就……"、为什么给例子比给形容词管用。想改造这些模板，先读那一篇。

某条模板你每周都要用一次，就该[把它做成 Skill](../skill/)了。
:::

## 0 · 万能骨架

不知道该怎么写的时候，从这个开始填空：

```text
你是【角色】。

请【任务，一个明确的动词】。

背景：
【它必须知道但绝不可能自己知道的事：项目、客户、给谁看、有什么忌讳】

要求：
1. 【输出结构：分哪几块】
2. 【格式：表格 / 条目 / 段落，详略程度】
3. 【语气：正式 / 口语 / 对外 / 对内】

验收：
- 只能基于我给的内容，不要编造没提到的信息；
- 拿不准的地方标注「待确认」，不要自行猜填。

材料如下：
【粘贴你的原始材料】
```

## 1 · 会议纪要

本书 [08 章](../start/08-first-task) 的主线例子。

```text
你是一位专业的项目助理。请把下面这段零散的会议记录，整理成一份结构清晰的会议纪要。

背景：这是【我方 / 内部】与【参会方】就【项目名】的一次【沟通会 / 评审会 / 例会】，
参会方包括【列出角色，比如：我方项目组、客户市场部（刘总监）、客户技术人员】。

请按以下三块输出：
一、关键结论 / 已定事项
二、待办事项（每条标出：事项、负责人、截止时间）
三、遗留 / 待确认问题

要求：条目化、简洁，待办要能直接拿去派活。
只能基于我给的内容整理，不要编造没提到的信息；
负责人或时间不明确的，标注「待确认」，不要自行猜填；
人名一律沿用原记录里的称呼，不要补全。

会议记录如下：
【粘贴】
```

## 2 · 周报

```text
你是我的工作助理。请把我下面这些零散的工作记录，整理成一份可以直接发给主管的周报。

背景：我是【岗位】，汇报对象是【谁】，他关心的是【进度 / 风险 / 结果，挑一个】。

请按三块输出：
一、本周完成（每条一句话，写清结果而不是过程）
二、下周计划（每条标出预期产出）
三、需要支持（明确写出需要谁做什么，没有就写"暂无"）

要求：不写套话，不写"持续推进""稳步开展"这类词；
每条不超过两行；能写具体数字的地方写数字。

只能基于我给的内容，不要替我补充没做过的事。

工作记录如下：
【粘贴】
```

## 3 · 长文总结

```text
你是一位【领域】方向的资深分析师。请阅读下面的材料，输出一份摘要。

背景：这份材料是【来源和类型】，我读它是为了【你的真实目的：判断要不要跟进 / 准备明天开会 / 写汇报】。

请按以下结构输出：
1. 一句话结论（这份材料最重要的一件事）
2. 关键要点（不超过五条，每条一行）
3. 与我的目的相关的部分（重点展开）
4. 材料里提到但没说清的问题

要求：不要复述全文，不要写"本文主要讲述了"这种开场；
每一条结论后面标出它来自原文的哪一段（引用原文一句）。
原文里没有依据的，不要写。

材料如下：
【粘贴】
```

::: tip 第三条是这条模板的价值所在
"与我的目的相关的部分"——同一份材料，为了不同目的读，该抽出来的东西完全不同。不写这一句，你拿到的就是一份通用摘要。
:::

## 4 · 对外方案 / 汇报材料

```text
你是一位资深售前顾问。请基于下面的材料，起草一份给客户的【方案 / 汇报】初稿。

背景：客户是【谁】，对接人是【职位】，他关心的是【成本 / 风险 / 进度 / 效果】。
这份材料的用途是【他拿去向上汇报 / 我们现场讲 / 邮件发过去】。
需要避开的话题：【比如：不要提具体报价、不要承诺上线时间】。

请按以下结构输出：
一、我们对客户现状的理解
二、核心问题与目标
三、建议方案（分点，每点写清"做什么"和"解决什么"）
四、下一步与所需配合

要求：语气正式但不生硬，不用感叹号，不写"赋能""抓手"这类词；
每一部分控制在【N】段以内。

验收：所有事实、数字、时间只能来自我给的材料；
需要我补充信息的地方，用【待补充：xxx】标出来，不要自己编。

材料如下：
【粘贴】
```

## 5 · 原型描述 → PRD

比前面几条更硬核，但**用的还是同一套五要素**，只是"要求"那一格写得更细。

先把界面用文字描述清楚（不用会画图）：

```text
【原型｜预算偏差预警看板 - 首页】

· 顶部：四个数字卡片——总预算、已下单、偏差金额、偏差率。
· 中部：一张项目列表表格，每行是一个项目，列出该项目的预算、已下单、
  偏差金额、偏差率；偏差为负的金额标红。
· 表格可按"偏差金额绝对值"从大到小排序。
· 右上角：两个按钮——「上传对账表」（上传 Excel）、「导出」。
· 点某个项目行 → 向下展开，显示该项目下各成本子类的偏差明细。
· 顶部有筛选：按"大区"、按"项目状态"两个下拉。
```

然后：

```text
你是一位资深产品经理。我给你一个功能原型的文字描述，请基于它，
输出一份可以直接交给研发的 PRD（产品需求文档）。

背景：这是一个面向【使用对象】的【功能名】，用来【解决什么问题】。

请按以下结构输出 PRD：
1. 功能背景与目标
2. 目标用户与使用场景
3. 功能列表（一句话概览每个模块）
4. 各模块详细需求（含：字段、交互逻辑、计算规则）
5. 边界与异常处理
6. 验收标准

计算口径必须写清楚：【把你们的口径写死，比如：偏差金额 = 已下单 − 预算；
偏差为负不代表一定是"节约"，也可能是少下单或未下单，需要人工判断，
界面不要替用户下结论】。

验收要求：
- 不许臆造原型里没有的功能；
- 原型没说清的地方，统一放进文末「待产品确认」清单，不要自己假设；
- 面向研发，语言具体、可执行，不要空话。

原型描述如下：
【粘贴上面那段】
```

::: tip 这条模板最值钱的一句
是"原型没说清的地方，统一放进文末「待产品确认」清单"。它不替你拍板，而是**把该问产品的问题都替你列出来**——这一段往往比 PRD 正文更有用。
:::

## 6 · 改写与润色

```text
请把下面这段话改写成【更正式 / 更口语 / 更简短 / 更适合发给客户】的版本。

要求：
- 意思一个字都不能改，尤其是数字、时间、承诺和否定；
- 不要增加原文没有的信息；
- 【长度：控制在原文的一半 / 分成三段 / 每句不超过 25 字】；
- 给我两个版本，我自己挑。

原文：
【粘贴】
```

## 7 · 找茬 / 审稿

反过来用，让它当审稿人：

```text
你是一位挑剔的【角色，比如：法务 / 技术评审 / 客户方项目经理】。
请审阅下面这份材料，找出问题。

审的角度：
1. 逻辑上说不通或前后矛盾的地方
2. 有承诺风险、可能被抓字眼的表述
3. 缺失的关键信息（读者一定会问但材料没答的）
4. 数字、时间、口径不一致的地方

要求：按严重程度排序，每条写清"在哪里、什么问题、怎么改"；
不要夸奖，不要总结全文，只给问题。
没找到问题的类别，直接写"无"。

材料如下：
【粘贴】
```

## 8 · 让它先问我（对付"我也说不清想要什么"）

需求自己都没想清楚的时候，这条最好用：

```text
我想让你帮我做【一件事的粗略描述】。

先不要动手。请先问我 5 个问题，问那些**你不知道就一定会做错**的事。
一次把 5 个问题列出来，我一起答。

我回答完之后，你再开始做。
```

它问出来的问题，往往就是你没想清楚的地方。

## 9 · 分类打标（批量场景）

```text
你是数据标注员。请把下面每一条内容归到指定分类里。

分类定义：
- A【类别名】：【什么算 A，举一个例子】
- B【类别名】：【什么算 B，举一个例子】
- C 其他：不属于以上任何一类

要求：
- 每条只输出一行，格式为：编号 | 分类 | 判断依据（不超过十个字）
- 拿不准的归到 C，并在依据里写"待人工"
- 不要解释，不要写开场白

内容如下：
1. 【…】
2. 【…】
```

## 10 · System Prompt 模板

设一次，整段对话都生效。→ [07 章](../start/07-system-prompt)

```text
你是【使用者的岗位】的助理，服务对象是【谁】。

通用规矩：
1. 输出默认用简体中文，条目化，能用表格就用表格。
2. 对外文档语气正式；内部沟通直白，不要客套话。
3. 任何数字、日期、人名，只能来自我给的材料。材料里没有的，
   标注「待确认」，不要根据常识补全。
4. 你不确定的时候，明确说"我不确定"，并指出需要我补充什么信息，
   不要给一个看起来完整的答案。
5. 不要在回答开头复述我的问题，直接给结果。
6. 【你们团队的专属规矩：术语、忌讳、格式要求】
```

## 附：三个可以加到任何模板末尾的"补丁"

**要它给出处**（只在你提供了材料时用）：

```text
每一条结论后面标出它来自我给的材料的哪一段（引用原文一句）。
材料里没有依据的，不要写。
```

**要它自查一遍**：

```text
写完之后，请对照上面的要求逐条自查一遍，把不满足的地方改掉再输出。
不要把自查过程写出来，只给最终结果。
```

**要它给几个版本**：

```text
给我三个方向不同的版本，各用一句话说明这一版的取舍，我来挑。
```
