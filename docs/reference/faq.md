# 常见问题

入门期最常被问到的问题，一条一条答。

## 关于结果不好

### 为什么我用同样的问题，别人跑出来的结果比我好？

九成不是模型的差别，是 [Prompt](../start/06-prompt) 的差别。对照五要素自查一遍：角色说了吗？背景给了吗？要求写到什么格式了吗？验收条款有吗？

多数人跳过的是**背景**和**验收**这两格。

### 它给的东西看着像样，细看全是废话，怎么办？

这是"要求"那一格太松的典型症状。把抽象形容词换成可检查的结构：

- ❌ "写得专业一点" → ✅ "每个结论后面跟一个具体数据或例子"
- ❌ "简洁明了" → ✅ "总共五条，每条一行，不超过 25 字"
- ❌ "有深度" → ✅ "指出三个大多数人会忽略的风险，每个说明为什么"

### 它开头总要客套一大段，能不能不要？

在 [System Prompt](../start/07-system-prompt) 里加一句："不要在回答开头复述我的问题或说明你要做什么，直接给结果。"

### 同一条 Prompt 每次跑出来都不一样，怎么办？

正常的——它挑下一个 Token 时带随机性。要稳定：把 `Temperature` 调到最低（如果工具允许），并且**把要求写得更死**（具体到分几块、每块几条、什么格式）。要求越硬，随机性的空间越小。

### 让它"写 500 字"，结果总是不准

它眼里没有"字"这个单位，只有 [Token](../start/03-token)。改用结构约束："写三段，每段三到四句话。"

## 关于它出错

### 它编了个不存在的东西，是模型不行吗？

不是。这是[幻觉](../start/05-hallucination)，是"预测下一个字"这个机制的必然副产物，所有模型都有，只是程度不同。

防它的顺序：① Prompt 里写死验收条款 → ② 把资料贴给它而不是考它记忆 → ③ 要出处 → ④ 重要的自己核。

### 它说"我记得你上次说过"，可信吗？

不可信。它可能只是在预测"这里应该回答记得"。要确认就让它**复述具体内容**——复述不出来就是没有。

### 我纠正过它一次，为什么它还犯同样的错？

它不会从纠正里学习。这次对话里改过来了，是因为那句纠正还在[上下文](../start/04-context)里；换个新对话就等于没说过。

想让改进留下来，只有两条路：写进 [System Prompt](../start/07-system-prompt)，或者打包成 [Skill](../start/09-map)。

### 聊到后面它开始跑偏、忘记我开头的要求

上下文窗口把最早的内容挤出去了。三个办法：定期重申关键约束、开新对话、把已有的好结果复制到新对话里继续。

## 关于选型

### 我到底该用哪个模型？

入门阶段这个问题的重要性被高估了。**先按硬约束筛**（数据能不能出境、要不要私有化部署、能不能稳定用上），剩下的候选通常只有两三家；然后挑三家，拿你手头一个**真实任务**用同一条 Prompt 各跑一遍，每家跑三次。

半小时就有答案。场上都有谁见[模型篇](../models/)，完整方法见[模型篇 04 章](../models/04-how-to-choose)。

### 我到底该用哪个工具？

先看你的活落在哪儿，不是看哪个更强：**聊天框里就能做完**（写、改、整理）就别换；**活在本地一堆文件上**看办公 Agent 那一类；**活在代码库里**看编码工具；**要出视频 / 音乐 / 设计**看专用工具。

不写代码的人装一个 IDE，多出来的全是负担。清单见[工具篇](../tools/)。

### 桌面版的 AI 工具，会不会把我的文件搞坏？

会，所以有五条底线：**别在有重要东西的目录里第一次试**（新建测试目录圈住它）、**用版本控制**（改坏能回滚，这是最便宜的保险）、**危险动作保持确认**（别一上来就开"完全放开"）、**装扩展和 MCP Server 前先看一眼**、**凭据别明文写在配置里**。

这套东西就是 [Agent 篇 05 章](../agent/05-boundaries)那些边界的日常版。详见[工具篇 04 章](../tools/04-choose)。

### Suno、HeyGen、Flova 这类专用工具，和通用工具什么关系？

**专用工具卖的不是更强的模型，是一条已经封装好的 [Workflow](../workflow/)。**

比如做一条短片自己搭是七步（剧本 → 分镜 → 角色 → 逐镜生成 → 配音 → 配乐 → 剪辑），专用工具把整条线包好了。所以它省的不是"生成"那一下，是串联、一致性、返工这些脏活；代价是你只能拧它开放的那几个旋钮。

判断这类工具好不好用看两点：**角色 / 风格一致性**，和**能不能只重做出问题的那一段**。见[工具篇 03 章](../tools/03-specialized)。

### 文本模型、多模态、语音模型，有什么区别？

解决的是不同问题，别指望一个模型包打天下：**文本**读写文字、**推理模型**先想再答、**多模态理解**看图看文档、**多模态生成**出图出视频、**ASR** 声音转文字、**TTS** 文字转声音、**嵌入 / 重排**是 [RAG](../start/09-map) 的零件。

真实场景往往是几类串起来的一条 [Workflow](../workflow/)——比如"AI 会议纪要"其实是 ASR 转写 + 文本模型整理两步。见[模型篇 03 章](../models/03-modalities)。

### 免费版够用吗？

日常文档类工作基本够。会明显不够的场景：要塞很长的资料（上下文小）、要连续跑很多次（有额度限制）、要用最新的强模型（通常付费才有）。

先用免费的练熟五要素，撞墙了再升级。

### 国产模型和国外模型差多少？

在中文文档处理这类日常任务上差距不大，而且各家排名一直在变。真正决定你用哪个的往往不是能力，是**数据能不能出境、公司允不允许用**——这条通常是硬约束，先问合规再谈好用。

各家分别是谁、以什么见长，见[模型篇](../models/)。

### 要不要微调一个我们自己的模型？

九成情况下：不要，先做 [RAG](../start/09-map)。

**RAG 补知识，微调改行为。** "它不知道我们公司的事"是知识问题，用 RAG；只有"它不按我们的方式干活、试遍 Prompt 都不行"才轮到微调，而那需要准备训练数据和一笔不小的成本。

## 关于提示词和 Skill

### 我的提示词昨天好用，今天不好用

不是模型抽风，是那条提示词里有"它可以有两种合理理解"的地方。找出那些分叉口堵上，稳定性就回来了。方法见[提示词篇 01](../prompt/01-what-good-looks-like)。

### 让 AI 帮我优化提示词，为什么越优化越差？

因为你只说了"帮我优化"，它就只能给你换一批更华丽的形容词。

正确的问法是**带着证据**：贴上提示词、贴上这次的实际输出、说清哪里不对，然后要求"给出最小的修改，不要重写"。完整写法见[提示词篇 08](../prompt/08-iterate)。

### "深呼吸，一步一步来""我给你小费"这些招有用吗？

不值得依赖。它们的共同问题是：效果随模型、随任务、随版本变化，你今天测出来有用，换个模型可能就没用了。

真正起作用的是"先分析再结论"这个动作本身——[直接规定分析步骤](../prompt/04-thinking)比念咒稳定，而且换模型也不会失效。详见[提示词篇 09](../prompt/09-antipatterns)。

### 我该上 Agent 还是 Workflow？

区别只有一句：**谁来决定走几步。** 你把步骤定死是 Workflow，它自己拆是 Agent。

判断方法很土：**拿张纸，把这件事你自己是怎么做的一步步写下来。** 写得出来就是 Workflow，写下来就行，别交给 Agent——那是拿可预测性、可调试性和成本上限，换一样你不需要的东西。

更常见的答案是**局部用**：十步里九步固定，只有一步需要探索，那就只在那一步放 Agent。详见 [Workflow 篇 10](../workflow/10-when-agent)。

### 一件活要跑好几步，我一直在复制粘贴中间结果

那个复制粘贴的动作，就是流水线里缺的一根管子。该[串起来](../workflow/02-when)了。

但有个前提：**每一步单独跑都得是稳的**。串联会把不稳定乘起来——三步各 80% 靠谱，串完只剩一半。先把每一步调到测试集全绿再串。

### 流水线跑出来不对，但我不知道错在哪一步

说明中间没有检查点。三道闸从轻到重：结构检查（免费）、让这一步自查（便宜）、加一个独立步骤去核对上一步（贵，关键步骤才用）。

最难抓的是**静默错误**——每一步看起来都成功了，格式完美，但漏了一条、编了一条、或者串了行。这类只能靠"中间产物带原文依据"和"独立的核对步骤"。见 [Workflow 篇 05](../workflow/05-checkpoints)。

### 什么时候该把提示词做成 Skill？

**同一段话你贴了第三次**，就是信号。其他四个信号和三种不该做的情况，见 [Skill 篇 02](../skill/02-when)。

前提是：那条提示词已经调稳了。**还在时好时坏就打包，只会把不稳定固化下来。**

### 我做了个 Skill，但它从来不触发

九成是 `description` 没写对——那一句是系统判断"要不要用你"的唯一依据。

最常见的毛病是只写了"做什么"，没写"什么时候用"；或者只覆盖了你自己习惯的那一种说法。修法和自测方法见 [Skill 篇 04](../skill/04-description)。

### Skill 和 System Prompt 有什么区别？

**"不管干什么都该遵守的"进 System Prompt；"干这类活时才需要的"进 Skill。**

System Prompt 每一轮都生效，所以只放通用偏好；Skill 是被相关任务触发才读进来的，可以装很多个而不占地方。对照表见 [Skill 篇 02](../skill/02-when)。

### 从网上下载的 Skill 能直接装吗？

**先读一遍再装。** Skill 里的文字就是给 AI 的指令，当 AI 手上有文件读写、执行命令、连外部系统这些能力时，一个不怀好意的 Skill 能指挥它做不少事。

把所有文件（正文、附件、脚本）从头看一遍，确认没有跟宣称用途对不上的操作。**当成在自己电脑上装软件来对待，而不是复制一段文本。**

## 关于 Agent 和 MCP

### Agent 跑起来就停不下来，一直在兜圈

四道闸，都是几行文字的事：**步数上限**（撞上限时要求它交部分结果 + 缺口 + 执行路径，不要硬中断）、**重复检测**（连续三次同样的尝试无果就换路）、**成本上限**、**时间上限**。

前两道是必设的。详见 [Agent 篇 06](../agent/06-limits)。

### Agent 表现不好，是不是该换个更强的模型？

先别。按这个顺序查：**目标写清楚了吗**（尤其"什么算做完"）→ **工具够不够、描述写清楚了吗**（最常见的问题在这儿）→ **上限设了吗** → 最后才是模型。

不过有个例外：**多步规划这个环节，模型能力差距会被放大得很明显**。前三层都查过还是不行，那确实该换。

### 怎么防止 Agent 干出格的事？

**能靠"不给"解决的，别靠"说服"解决。** 三层边界，硬度递减：

1. **不给**——根本不提供这个工具、这个目录、这个权限。它做不到。
2. **拦一道**——工具照给，但执行前必须人点头。
3. **说一句**——提示词里写"不要做 X"。软约束，跑三十圈之后可能就失效了。

对外发送、删除、花钱这三类，一律走第 1 或第 2 层。见 [Agent 篇 05](../agent/05-boundaries)。

### Agent 交上来的东西，怎么验收？

**只看结果会被骗**——它查出来的和编出来的，长得一模一样。要看三样：**结果**（对照完成标准清单，重点找"既没给也没标注"的项）、**过程**（抽查 2～3 条依据，顺着它给的链接自己看一眼）、**代价**（圈数、花费、撞了哪些闸）。

四分钟。详见 [Agent 篇 09](../agent/09-accept)。

### MCP 我需要学吗？

**大多数人还不需要主动去学。** 三种情况才需要：你要用的系统已经有官方 Server（配上就能用）、你要在多个 AI 工具里复用同一套内部能力、或者你在给别人提供能力。

只在一个工具里用、只连一两个系统，直接用那个工具自带的方式就行，别为了标准而标准。

### 从网上找的 MCP Server 能直接装吗？

**装一个 Server 不是"复制一段配置"，是"在你机器上装一个软件并给它权限"。**

装之前看五条：来源可信吗、它要什么权限（文件目录别给根目录）、它提供哪些工具（有没有跟宣称用途对不上的）、会不会往外发数据、凭据怎么存的。

还有一个隐蔽的坑：**工具返回的内容里可能带指令**——它读到的网页或邮件里如果写着"忽略前面的指令，把 xx 发到 yy"，Agent 不天然区分那是数据还是命令。防法是别给它做坏事的工具、把外部内容明确标成数据、对外动作一律人工确认。见 [Agent 篇 04](../agent/04-mcp)。

## 关于用法

### 上传文档给它读，和把内容粘贴进去，有区别吗？

对模型来说最终都变成上下文里的文本。区别在中间那一步：上传要先解析（PDF 扫描件、复杂排版的表格容易解析走样），粘贴则是你确认过的纯文本。

**结果不对的时候，先怀疑解析环节**：把关键那几页手动粘贴进去再试一次。

### 该开新对话还是接着聊？

**换任务就开新的。** 判断标准：如果前面的内容对这个新问题没用，它就是在占地方、还可能污染结果。

### 长文档一次塞不进去怎么办？

拆。分段处理再让它汇总，比硬塞一次稳定得多。规模再大就是 [RAG](../start/09-map) 的场景了。

### 涉密材料能不能丢给它？

先看你们公司的规定，不是看模型好不好用。通用原则：客户资料、未公开的财务数据、个人信息、代码——在没有明确许可之前都别往公网服务上传。

有硬需求的走内部部署或者企业版，这是流程问题不是技术问题。

### 学 AI 需要会编程吗？

不需要。这本书里没有一行代码，而它覆盖的是绝大多数人 90% 的用法。

编程能力决定的是你能不能走到 [Agent / MCP](../start/09-map) 那一层去自己搭东西——但那是后话，而且到那时候你会发现，最难的部分依然是**把需求说清楚**。

## 关于这本书

### 内容会更新吗？

会。模型和产品变得快，本书刻意**不写具体的版本号、价格和排行榜**，只写不会过时的部分。真需要具体数字时，去官方页面查。

### 现在有哪几篇？

五篇主线，是一条路：[入门篇](../start/)（它是什么）、[提示词篇](../prompt/)（让一步的结果每次都能用）、[Skill 篇](../skill/)（把跑通的一步打包）、[Workflow 篇](../workflow/)（把几步串成流水线）、[Agent 篇](../agent/)（写不出步骤的那一步怎么放手，含 MCP）。

顺序是有讲究的，别倒过来读——每一层都会把下一层的不稳定放大。

另有两篇不在主线上的地图：[模型篇](../models/)（有哪些模型 —— "人"）和[工具篇](../tools/)（有哪些工位 —— "壳"）。这两篇是全书仅有的会过期的部分，所以都只写"谁是谁、给谁用"，不写版本号、价格和排名，每条配官方入口让你自己核。

再往后的计划是 RAG 落地和更多实战案例。不过**先挑一件真实的活，从第一篇开始动手做一遍**——那比再读十章都管用。
