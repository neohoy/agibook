# 08 · 上手：把一坨乱记录变成能派活的纪要

这一章不讲新概念，只干一件事：把前面七章的东西**在一个真实任务上跑通一遍**。

选会议纪要当例子，是因为它足够普通——几乎每个岗位都要写，材料你手边就有，好坏一眼能看出来。跟着做，大概十分钟。

::: tip 打开任意一个 AI 聊天框
GPT、Claude、豆包、DeepSeek、Kimi、通义都行。这一章的每一步在哪家都成立。
:::

## 第一步：材料（一段真实的乱记录）

会开完随手记的东西，大概长这样。整段复制备用：

```text
今天跟客户(明远地产)开了快一个钟头吧,主要聊下半年那个会员小程序改版。对接人是
他们市场部的刘总监,还有个技术那边的小哥忘了叫啥。刘总监一上来就说首页那个 banner
一定要能后台自己换,不想每次找我们,这个挺重要的。然后聊到积分商城,他们想加个秒杀,
但具体规则没定,说下周内部再对一下给我们。哦对中间还插了一句说预算可能比上次说的紧,
让我们报价的时候注意点。技术小哥提了个事,说他们现在用的还是老的支付接口,改版得一起
升级,不然对不上。然后纠结了半天上线时间,客户想赶在双十一前,我说研发评估下来九月底
设计定稿、十月中提测比较稳,刘总监说那行先按这个,但要我们这周五之前先给一版改版的
整体方案他好往上汇报。还有个事差点忘了,他们要我们把上次那个数据报表的权限分一下,
不同门店只能看自己的,这个王工你跟进一下。大概就这些,散会的时候说下周二再碰一次。
```

这段材料好在它很脏：里面混着**已经定的事**、**要办的事**（有的带人名有的不带）、**还没定的事**，还有一句跑题的预算。真实的会议记录就是这样。

## 第二步：先感受一下"含糊地说"

先别用五要素。原样发这句：

```text
帮我把这个会议记录整理一下。
【粘贴上面那段】
```

你拿到的大概率是一段**重新排版的流水账**：它把你说的话换个说法复述一遍，段落变整齐了，但——

- 待办事项还埋在句子里，没拎出来；
- 没有责任人，没有截止时间；
- "还没定"和"已经定"混在一起；
- 运气不好的话，它给"刘总监"补了个全名，或者给会议编了个日期。

**这一步别跳过。** 你得先看见坏结果，好结果的价值才成立。

## 第三步：五个问题，拼出一条好 Prompt

现在一格一格补。每一格先自己想答案，再看我给的。

::: details 1. 角色 —— 让它扮谁？
```text
你是一位专业的项目助理。
```
:::

::: details 2. 任务 —— 具体干什么？
```text
请把下面这段零散的会议记录，整理成一份结构清晰的会议纪要。
```
:::

::: details 3. 背景 —— 它得知道什么才不会瞎猜？
```text
背景：这是我方与客户「明远地产」就"会员小程序改版"项目的一次沟通会，
参会方包括我方、客户市场部（刘总监）和客户技术人员。
```
它不知道"明远地产"是客户不是同事，不知道"王工"是我方的人，不知道这是对客会。这些你觉得废话的信息，正是它缺的。
:::

::: details 4. 要求 —— 纪要要长什么样？（★ 停久一点）
```text
请按以下三块输出：
一、关键结论 / 已定事项
二、待办事项（每条标出：事项、负责人、截止时间）
三、遗留 / 待确认问题

要求：条目化、简洁，待办要能直接拿去派活。
```
如果你刚才只想到"整理清楚一点"，回头看一眼——**清楚是什么样？分几块？谁该干什么要不要单拎出来？** 这一格写多细，结果就有多可用。
:::

::: details 5. 验收 —— 怎么保证它没编？
```text
只能基于我给的内容整理，不要编造没提到的信息；
负责人或时间不明确的，标注「待确认」，不要自行猜填。
```
:::

## 第四步：完整的 Prompt

五格拼起来就是这一条，可以直接复制：

```text
你是一位专业的项目助理。请把下面这段零散的会议记录，整理成一份结构清晰的会议纪要。

背景：这是我方与客户「明远地产」就"会员小程序改版"项目的一次沟通会，
参会方包括我方、客户市场部（刘总监）和客户技术人员。

请按以下三块输出：
一、关键结论 / 已定事项
二、待办事项（每条标出：事项、负责人、截止时间）
三、遗留 / 待确认问题

要求：条目化、简洁，待办要能直接拿去派活。
只能基于我给的内容整理，不要编造没提到的信息；
负责人或时间不明确的，标注「待确认」，不要自行猜填。

会议记录如下：
【粘贴第一步那段】
```

## 第五步：你会拿到什么

大致是这样一份东西（不同模型措辞会有出入，结构应该一致）：

---

### 明远地产 · 会员小程序改版｜项目沟通会 纪要

**会议日期**：待确认（原记录未注明）　**参会方**：我方；客户市场部（刘总监）、客户技术人员（姓名待确认）

**一、关键结论 / 已定事项**

1. 首页 banner 改为**后台可自行更换**，客户无需每次联系我方。
2. 上线节奏初步确定：**9 月底设计定稿、10 月中提测**，目标赶在双十一前上线（刘总监已认可）。
3. 改版需**同步升级支付接口**（现用旧接口，否则数据对不上）。

**二、待办事项**

| 事项 | 负责人 | 截止时间 |
| --- | --- | --- |
| 提交一版改版整体方案（供客户向上汇报） | 我方 | 本周五前 |
| 数据报表权限分级（各门店仅看本店） | 王工 | 待确认 |
| 反馈积分商城秒杀的具体规则 | 客户（内部对齐后） | 下周内 |
| 报价时留意预算收紧情况 | 我方 | 方案 / 报价阶段 |

**三、遗留 / 待确认问题**

1. 积分商城秒杀规则未定，待客户内部对齐。
2. 预算较上次"可能收紧"，具体口径未明确。
3. 下次沟通：**下周二**再碰一次。

---

对比第二步那段流水账：**同一段材料，同一个模型，只因为话说清楚了，结果从"看看得了"变成"能直接发群里派活"。**

## 第六步：验收（别跳过这一步）

拿到结果先扫这四条：

| 检查 | 为什么 |
| --- | --- |
| 有没有原文里**没有**的人名全称、具体日期？ | 它最爱干的就是这个，见 [05 · 幻觉](./05-hallucination) |
| "待确认"该标的地方标了吗？ | 没标说明验收那一格没生效，把它补严 |
| 待办拿出去，别人看得懂要干嘛吗？ | 看不懂就是"要求"那一格写细一点 |
| 有没有把"还没定的"写成"已经定了"？ | 这是最危险的一类错——会直接误导下游 |

<div class="ab-do">

第一条如果中了（它给刘总监补了全名，或者编了个会议日期），**别急着骂它**。这正好是[验收那一格](./06-prompt)存在的理由：把 "不要自行猜填" 改得更硬一点，比如加一句"人名一律用原记录里的称呼，不要补全"，再跑一次。

调 Prompt 比调模型有用得多。
</div>

## 换个活，同一套方法

把上面这条 Prompt 的五格替换掉，就是另一个任务。这不是巧合——**是这一套方法本来就与任务无关**：

| 任务 | 角色 | 要求那一格换成 |
| --- | --- | --- |
| 周报 | 你是我的工作助理 | 分"本周完成 / 下周计划 / 需要支持"三块，每条一句话 |
| 客户方案 | 你是资深售前顾问 | 分"客户现状 / 我们的理解 / 建议方案 / 下一步"，语气正式 |
| 面谈复盘 | 你是招聘经理 | 分"候选人亮点 / 疑虑 / 待验证问题 / 建议结论" |
| 需求整理 | 你是资深产品经理 | 分"背景目标 / 功能列表 / 详细需求 / 边界异常 / 待产品确认" |

最后一行往上走一层，就是"把一个原型描述自动变成一份 PRD"——同样五要素，只是任务更硬核。完整模板在[提示词模板库](../reference/prompts)。
