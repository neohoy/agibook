# 10 · 选模型、选工具，和入门期的十条铁律

最后一章，两件事：怎么挑，以及别踩坑。

## 一、怎么挑模型

先说结论：**入门阶段，选哪家的影响，远小于你怎么交代任务的影响。** 你在 [08](./08-first-task) 已经验证过这一点了——同一个模型，话说清楚和说不清楚，差得比换一家模型大得多。

所以别在这上面纠结太久。真要挑，看这几个维度就够：

| 维度 | 怎么判断 |
| --- | --- |
| **任务类型** | 长文写作 / 代码 / 数学推理 / 多语言，各家强项不同，拿你的真实活试一遍最准 |
| **上下文窗口** | 你要塞长文档就看这个，见 [04](./04-context) |
| **价格** | 按 [Token](./03-token) 算。同一家往往有"旗舰 / 均衡 / 便宜"三档，别默认用最贵的 |
| **速度** | 交互式用（边聊边改）优先快的；批量跑用便宜的 |
| **是否推理型** | 会先"想"一段再答的那类，难题上明显更强，但慢、贵。简单活别用 |
| **数据合规** | 材料涉不涉密、能不能出境、能不能私有化部署——这条通常是硬约束 |
| **开源 / 闭源** | 需要自己部署、二次开发就看开源模型；只要好用就用闭源的托管服务 |

::: tip 别信排行榜，信你自己的活
榜单是拿标准题测出来的，跟你的业务没关系。**挑三家，拿你手头一个真实任务，用同一条 Prompt 各跑一遍**——半小时得到的结论，比读十篇评测靠谱。

想知道场上都有谁、各家以什么见长，见[模型篇](../models/)；那里也有这个测法的完整版和"先按硬约束筛"的顺序。
:::

### 一个花钱的实用建议

同一家的模型通常分几档。默认全用最强那档，是最常见的浪费：

- **简单活**（格式转换、分类、摘要、改写）用便宜档就够，快还省钱。
- **难活**（复杂推理、长文档分析、写代码）再上强档。
- **要稳定重复跑的活**，先在强档上调通 Prompt，再试试降档还能不能过——很多时候能。

## 二、怎么挑工具

工具是"工位"，模型是"人"。同一个模型装在不同工位里，能干的事差别很大（完整清单见[工具篇](../tools/)）：

| 类型 | 代表形态 | 适合 |
| --- | --- | --- |
| **网页 / App 聊天框** | ChatGPT、Claude、豆包、DeepSeek、Kimi、通义 | 绝大多数日常文档类工作。入门就用这个，别折腾 |
| **带项目 / 智能体的产品** | 各家的 GPTs、智能体、Project、知识库 | 同一套规矩反复用（就是 [Skill](./09-map)） |
| **命令行 / IDE 里的编码工具** | Claude Code、Codex、Cursor 等 | 要读写本地文件、跑命令、改代码 |
| **企业内部平台** | 各公司自建 | 数据不能出内网的场景 |
| **API** | 直接调接口 | 要批量跑、要嵌进自己的系统 |

<div class="ab-do">

**入门期就用一个网页聊天框，别折腾工具。**

先把五要素练熟，一个月内你能明显感觉到自己开的活质量在涨。那时候你自然会知道自己缺什么工具——**是因为遇到了具体的墙才去换工具，不是因为看了篇文章说某个工具牛。**

## 三、入门期的十条铁律

这十条是前面九章的浓缩。打印出来贴桌上都行。

**1. 它是在预测下一个字，不是在查资料。** 所有毛病都从这来。

**2. 重要的东西，自己核。** 数字、日期、人名、引用、法条——一条都别信。

**3. 你觉得"这还用说吗"的信息，正是它不知道的。** 背景那一格，多写一句总没错。

**4. 含糊的要求换来含糊的结果。** "整理一下"永远不如"分三块，第二块带责任人和截止时间"。

**5. 每次都要重说的话，搬进 System Prompt。**

**6. 一个任务一个对话。** 跑偏了就重开，别在原对话里硬掰。

**7. 用字数当验收标准一定翻车。** 改成结构约束。

**8. 说不清想要什么格式，就给两个例子。** Few-shot 比形容词有用。

**9. 一次只让它干一件事。** 三个诉求塞一段话，三个都做不好。

**10. 先把话说清楚，再谈让它自己跑。** 顺序反了，只会更快地拿到垃圾。

## 四、然后呢

入门篇到这里就结束了。你现在应该能做到：

- 用一句话讲清楚它为什么会编、为什么会忘；
- 拿到一个活，能自己拆出角色 / 任务 / 背景 / 要求 / 验收五格；
- 看见 RAG、Agent、MCP、微调这些词，知道它们各自解决什么问题、跟你现在有没有关系。

接下来往哪走，看你的实际需要：

- **结果时好时坏，想让它稳定下来** → [提示词篇](../prompt/)。十一章，讲怎么把一条提示词调到"谁跑、跑几次都能用"。
- **同一段话已经贴了第三次** → [Skill 篇](../skill/)。把规矩打包，一句话触发，团队共用一版。
- **一件活要跑好几步，你在复制粘贴中间结果** → [Workflow 篇](../workflow/)。串成流水线，每步能验收，错了知道停在哪。
- **有一步你根本写不出步骤** → [Agent 篇](../agent/)。放手让它自己跑，但要先划好边界、设好上限。MCP 也在这一篇。
- **想把手头的活套模板** → [提示词模板库](../reference/prompts)，挑一个改改就能用。
- **想知道市面上都有哪些模型** → [模型篇](../models/)。国外国内各家是谁，以及文本 / 多模态 / 语音分别解决什么问题。
- **想知道有哪些工具能装** → [工具篇](../tools/)。桌面版的通用工具，以及音乐 / 数字人 / 短剧 / 设计这些专用工具。
- **哪个词又忘了** → [术语表](../reference/glossary)，一页查完。
- **还有疑问** → [常见问题](../reference/faq)。

**但顺序别倒过来。先把这一篇的十条用满一个月**——上面那三篇，每一篇的前提都是"你已经能把一件事说清楚"。
