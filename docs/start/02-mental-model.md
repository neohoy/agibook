# 02 · 心智模型：把它当成刚入职的天才新人

<div class="ab-def">

别把它想成"软件"，想成"**人**"——一个特别聪明、但**今天才第一天上班**的新人。这个比喻能一路用到最后，本书剩下的所有概念都往这个人身上挂。

</div>

## 这位新人的工牌

| | |
| --- | --- |
| **姓名** | AI |
| **职位** | 天才新人 |
| **入职** | 第一天 |
| **状态** | 试用期 |

**他很能干**：文能写方案，武能改代码，学历吓人，各行各业都能聊两句。

**但他有三个毛病**，你带过新人就懂：

1. **不懂你们公司的规矩。** 不知道你们客户是谁、报价多少、流程怎么走、"周五前"是指几点。
2. **你不说清楚，他就自由发挥。** 而且发挥得特别自信，交上来的东西看着像回事，细看全是他自己脑补的。
3. **不懂装懂。** 答不上来也不说"我不知道"，而是给你编一个——**这是最要命的一条**。

<div class="ab-do">

带 AI 跟带新人一模一样：**你交代得越清楚，他干得越好；你越甩手，他越容易给你捅娄子。**

这本书剩下的部分，本质就在教一件事——怎么把这个天才新人带明白。

</div>

## 为什么这个比喻比"工具"好使

因为"工具"这个词会让你产生两种错误预期：

- **要么把它当扳手**——按一下就该出正确结果，出错了就是"这工具不行"。于是你换一家模型，发现还是那样。
- **要么把它当同事**——以为交代一次它就记住了，以为它会主动确认，以为它拿不准会来问你。它不会。

"天才新人"这个比喻正好卡在中间：他有能力，但没有你们公司的上下文，也没有职场人那种"拿不准就问一句"的自觉。你得替他补上这两块。

## 一个反例，说明"新人"这个比喻在哪里会失效

比喻好用，但别当真理。有两处它和真人不一样，踩过的人都吃过亏：

**真人会累，他不会。** 同一件枯燥的活让他干五十遍，质量不会下滑。所以重复性的活值得交给他，哪怕你自己干更快——你的时间比他贵。

**真人会成长，他不会。** 你今天纠正他一个错误，明天开个新对话，他照错不误。**他不会从你的纠正里学习**。想让改进留下来，只有两条路：每次都重讲一遍（累），或者把规矩写进 System Prompt / Skill 里（见 [07](./07-system-prompt) 和 [09](./09-map)）。
