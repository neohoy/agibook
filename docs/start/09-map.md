# 09 · 全景地图：Prompt / Skill / Agent / MCP

你现在能把一件事说清楚了（[06](./06-prompt)、[08](./08-first-task)）。这一章回答的是"然后呢"——那些你在各种文章里刷到的词，彼此是什么关系，哪些现在就该学，哪些知道有这么个东西就行。

## 一条主线：越往后越省事

用带新人的说法，就是从"你盯着他"到"他自己跑"：

| | 概念 | 带新人 | 你要做的事 | 什么时候用 |
| --- | --- | --- | --- | --- |
| **01** | **Prompt** | 当面把活交代清楚 | 每次写一段话 | 一次性的活 |
| **02** | **Skill** | 给他一本 SOP 手册 | 把规矩打包存起来，一句话触发 | 每周都要重复的固定流程 |
| **03** | **Workflow** | 给他一张流程单 | 把步骤定死，一步步照着走 | 多步骤、但**每次都是同样几步**的活 |
| **04** | **Agent** | 放手让他自己跑 | 给一个目标，它自己拆步骤、执行、检查 | 多步骤、而且**事先不知道有几步** |
| **05** | **MCP** | 给他一张门禁卡 | 接上外部系统 | 需要连数据库、发消息、调工具时 |

::: warning 顺序不能反
**先会交代，才谈得上放手。** 一个连需求都说不清的人，直接上 Agent 只会得到一堆更快产生的垃圾。这是本书唯一一条关于学习顺序的硬建议。

顺带把最容易搞混的 03 和 04 先分清楚：**区别只有一个——谁来决定走几步。** 你把步骤写下来，就是 Workflow；让它自己拆，就是 Agent。**能写下来的，就该写下来。**
:::

### Skill —— 值不值得打包，看频率

你在 [08](./08-first-task) 写的那条纪要 Prompt，很好用。问题是：**下次开会你还得再写一遍。**

Skill 就是把这套规矩存下来，以后一句"按我们的规范整理成纪要"就触发。不同产品叫法不同——自定义 GPTs、智能体、技能、项目规则文件，本质都是同一件事：**把每次都要重讲的部分固化。**

判断标准简单到不用想：

> **一件事你只干一次，Prompt 就够；一件事你每周都干，就值得做成 Skill。**

### Workflow —— 大多数"自动化"其实是这个

真实的活很少只有一步：会开完 → 整理纪要 → 抽出待办 → 按人分组 → 生成派活消息 → 你过一眼 → 发出去。

六步，而且**每次都是这六步**。这种情况你要的不是一个会思考的东西，是**一条流水线**：每一步干什么、产出什么、交给下一步什么，全部由你事先定死。

好处很实在：错了知道错在第几步、改一步不影响别的、成本能算得出来。

判断标准跟 Skill 一样朴素：

> **拿张纸，把这件事你自己是怎么做的一步步写下来。写得出来，那就是一条 Workflow。**

这一格详见 [Workflow 篇](../workflow/)。

### Agent —— 它是一种工作模式，不是某个软件

你说"做份竞品分析"，它自己去搜资料、整理数据、成稿、再自查一遍。中间不用你插手——这个"自己跑完全程"的状态就叫 Agent（智能体）。

拆开看，Agent = **会规划**（先想清楚分几步）+ **能调工具**（搜索、读文件、跑代码）+ **能循环**（做完看一眼，不行就改）。三样凑齐，就是一个 Agent。

注意三点：**Agent 不是一个产品名**，市面上叫"XX Agent"的软件是把这套模式封装好了；**它跑得越自主，你越要在一开始就把目标说清楚**——中途你插不上手；以及最重要的一条——**一件你已经知道该怎么做的事，别交给它**。那种事写成 [Workflow](../workflow/) 更快、更便宜、错了还能定位。

真到了要放手的时候，怎么给目标、怎么划边界、怎么设上限、怎么验收，详见 [Agent 篇](../agent/)。

### MCP —— 一个统一的插头

模型本身[什么也做不了](./01-what-is-llm)。想让它查你的数据库、发条消息、调个内部系统，得给它接上。

以前每接一个系统都要单独写一遍对接代码，换个模型再写一遍。**MCP**（Model Context Protocol）把这件事标准化了：一次开发，各家模型都能用。类比就是 USB-C——以前每个设备一根线，现在一根线通吃。

这个你现在**知道有这么个东西就够了**。它是把 AI 从"只会说"接到"能动真格"的那道门，等你真需要连内部系统的时候再回来看——[Agent 篇 04 章](../agent/04-mcp)讲了它是什么、什么时候需要、以及装之前该检查什么。

## 中间还有一层：让它"能干活"的那些词

上面四个是主线。你还会刷到另一批词——它们解决的是同一个问题：**怎么让模型的输出能被下游程序用，以及怎么让它知道它本来不知道的事。**

| 词 | 一句话 | 带新人的说法 |
| --- | --- | --- |
| **Structured Output**（结构化输出） | 逼它按指定格式（通常是 JSON）输出，让代码能直接解析 | 要求他填表，而不是写小作文 |
| **Function Calling**（函数调用） | 模型决定"该调哪个工具、传什么参数"，**执行由你的代码干** | 他填一张工单，实际动手的是别人 |
| **RAG**（检索增强生成） | 先从你的资料库里检索出相关片段，再连问题一起塞给模型 | 派活时顺手把相关文件夹递给他 |
| **Embedding**（嵌入向量） | 把文本翻译成一串数字，意思相近的数字也相近 | 给每份资料贴一个"语义坐标" |
| **向量数据库** | 专门存这些数字、并能飞快找出"最接近的几条" | 那个按语义排好序的档案柜 |
| **微调**（Fine-tuning） | 用你的数据继续训练，改变模型本身的行为 | 送他去脱产培训 |

这一层不是入门必需，但有两个问题你迟早会被问到，先给你答案：

### RAG 和微调，什么时候用哪个

这是最高频的一道题，记住这一句就不会错：

> **RAG 补的是知识，微调改的是行为。**

| | RAG | 微调 |
| --- | --- | --- |
| 解决 | 它不知道我们公司的事 | 它不按我们的方式干活 |
| 怎么做 | 检索资料塞进上下文 | 拿数据重新训练 |
| 资料更新 | 改文档即可，立刻生效 | 得重新训一次 |
| 成本 | 低 | 高，还要准备训练数据 |
| 先试哪个 | **先试这个** | RAG 试过确实不行再考虑 |

九成的"我们要不要微调一个自己的模型"，答案是**先老老实实做 RAG**。

### 那 ChatGPT / Claude / Codex / 各种 IDE 算什么

它们是你安排新人干活的**工位**。

同一个新人，你让他在一张便签纸上办公（网页聊天框），还是给他一个配齐了流程、文件、工具的工位（编码类工具、企业内部平台），产出是不一样的。**但方法在哪个工位都通用**——你今天学的五要素，换到哪个工具上都成立。

有哪些工位、各自给谁用，见[工具篇](../tools/)；怎么挑，见 [10 · 选模型、选工具](./10-choose-and-rules)。
