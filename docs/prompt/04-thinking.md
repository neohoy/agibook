# 04 · 让它先想再答

<div class="ab-def">

模型是[一个字一个字往下接](../start/01-what-is-llm)的。这意味着**它一旦写下第一个字，后面就得顺着圆下去**——想不清楚也得往下写。所以对付复杂任务的通用招数只有一个：**别让它一上来就下结论。**

</div>

## 为什么"直接问"会翻车

问它"这三个方案哪个最划算"，它的第一个字很可能就是"方案"或者"第"——**在还没算过任何一笔账之前，它已经把答案选出来了**。后面那段"理由"，是给这个已经出口的结论补的。

这不是它不认真，是生成机制决定的：**结论如果出现在推理前面，推理就只能给结论打圆场。**

解法就四种，从轻到重。

## 招数一：让它把步骤写出来（思维链）

最简单的一句：

```text
先一步步分析，最后再给结论。
```

或者更具体地规定步骤：

```text
按这个顺序作答：
1. 先列出三个方案各自的成本项和金额
2. 再算出三年总成本
3. 再指出各自的隐性成本和风险
4. 最后才给推荐，并说明为什么排除另外两个
```

规定步骤比笼统的"一步步想"好用得多——**你把思考路径也定死了，稳定性跟着上来**。

::: tip 推理模型不用手动写这一句
会先"想"一段再答的那类模型（[推理模型](../reference/glossary)）已经内建了这个过程，你再写"请一步步思考"意义不大，有时反而干扰。但**规定具体步骤仍然有效**——那不是在教它思考，是在规定你要的分析框架。
:::

## 招数二：让它先反问你（对付"我也说不清"）

需求自己都还模糊的时候，最不该做的就是硬写提示词。改成这样：

```text
我想让你帮我做【一件事的粗略描述】。

先不要动手。请先问我 5 个问题，问那些**你不知道就一定会做错**的事。
一次把 5 个问题列出来，我一起答。

我回答完之后，你再开始做。
```

它问出来的那五个问题，往往就是你没想清楚的地方。**这一招的真正价值不是让 AI 更懂你，是让你自己想清楚。**

进阶版，用在需求复杂的时候：

```text
先不要动手。请分两步：
1. 用你自己的话复述一遍你理解的任务，包括你打算怎么做、分几步；
2. 列出你不确定、需要我确认的地方。

我确认之后你再开始。
```

第 1 步（让它复述）能提前抓住误解——**你会惊讶于它理解偏的频率**。

## 招数三：分步执行，一步一交付

复杂任务不要一条提示词干完。拆成几轮，每轮验收一次：

```text
第 1 轮：先只输出大纲，分几个部分、每部分讲什么，一行一个，不要展开。
（你检查大纲，改掉不对的）

第 2 轮：按确认后的大纲，只写第二部分，其他部分先不写。
（你检查这一部分的详略和语气）

第 3 轮：其余部分照第二部分的风格补齐。
```

好处有三个：**错了只用重跑一步**；**你能在中途改方向**；**每一步的输出更短，质量更稳**。

代价是慢。所以判断标准很简单：**一次能跑对的活别拆；跑三次都不满意的活，一定要拆。**

## 招数四：让它自己查一遍

在提示词末尾加这一段，几乎对所有任务都有效：

```text
写完之后，请对照上面的要求逐条自查一遍，把不满足的地方改掉再输出。
不要把自查过程写出来，只给最终结果。
```

更硬的版本是让它把检查结果显出来：

```text
输出分两部分：
一、正文
二、自查表：把上面每条要求列一行，标注「满足 / 不满足 + 原因」

自查表里有「不满足」的，就直接改正文，不要提交带问题的版本。
```

::: warning 自查不是万能的
它自查的依据还是它自己那套判断，所以**它编造的事实，自查也查不出来**——因为在它看来那就是真的。

自查能查的是：格式对不对、要求漏没漏、结构全不全。查不了的是：内容是不是事实。后者只能你自己核，见 [05 · 幻觉](../start/05-hallucination)。
:::

## 四招怎么选

| 症状 | 用哪招 |
| --- | --- |
| 结论下得草率、理由像是硬凑的 | 招数一：规定分析步骤 |
| 你自己也说不清要什么 | 招数二：让它先反问 |
| 输出总有几处不对，改了这里坏那里 | 招数三：拆成几轮 |
| 大方向对，但总漏掉某条要求 | 招数四：加自查 |
| 以上都试了还是不稳 | 回到 [02 章](./02-structure) 看结构，或者去 [08 章](./08-iterate) 学怎么定位 |

<div class="ab-do">

把招数四那三行（"写完之后逐条自查"）**加进你所有常用的提示词**，就当默认配置。

它几乎没有副作用，成本是多花一点输出 Token，收益是"漏掉某条要求"这类错误明显变少。

</div>
