# 01 · 好提示词的标准

<div class="ab-def">

判断一条提示词好不好，不看它写得漂不漂亮，看三条：**可复现**（跑十次都能用）、**可验收**（好坏有客观标准）、**可交接**（别人拿去也能跑出同样的东西）。

</div>

## 先搞清楚提示词到底在做什么

模型每一步都在从几万个候选字里挑一个。你的提示词做的唯一一件事，是**把它挑字的范围压小**。

- 你说"写点东西" → 范围大到没边，它挑什么都算"没错"。
- 你说"写一封给客户的道歉邮件" → 范围压到邮件、客气、道歉这一片。
- 你说"写一封给客户的道歉邮件，300 字内，先认错再给补偿方案，不要解释原因" → 范围压得只剩一条窄路。

**提示词写得越具体，可选的路越少，跑十次的结果就越接近。** 这也解释了为什么"输出不稳定"和"提示词太松"其实是同一件事的两种说法。

::: tip 一个立刻能用的判断
你觉得输出不稳定的时候，先别怪模型。把你的提示词读一遍，看有几处是"它可以有两种合理理解"的——每一处都是一个分叉口。堵住分叉口，稳定性自己就回来了。
:::

## 标准一：可复现

**同一条提示词，跑五次，五次的结果都能用。**

不是要求五次一模一样（那不可能，也没必要），是要求五次**都满足你的验收条件**：都分了三块、都带了责任人、都没编人名。

怎么测：把提示词跑五次，不改一个字。五次里有两次不合格，这条提示词就还不能用。

导致不可复现的常见原因：

| 原因 | 表现 | 怎么修 |
| --- | --- | --- |
| 要求用了形容词 | "写得专业一点"每次理解都不同 | 换成结构约束，见 [05](./05-format) |
| 没说清哪些是材料哪些是指令 | 有时它把材料里的话当成对它的命令 | 加分隔，见 [02](./02-structure) |
| 边界情况没交代 | 材料里缺信息时，有时标"待确认"，有时编一个 | 写死兜底规则，见 [06](./06-constraints) |
| 一条提示词干了三件事 | 每次挑不同的事做好 | 拆开 |

## 标准二：可验收

**你得能说出"这次输出哪里不合格"，而不是"感觉差点意思"。**

写提示词之前先问自己：这次的产物，我拿什么判断它对不对？把答案写进提示词，就是验收那一格。

坏的验收标准（没法判断）：

- 专业、有深度、结构清晰、逻辑严谨、语言流畅

好的验收标准（一眼能查）：

- 分成三块，标题分别是「结论」「待办」「遗留」
- 每条待办都有责任人和截止时间，没有的写「待确认」
- 全文不出现材料里没有的人名、日期、金额
- 总长度不超过一屏

<div class="ab-do">

写完提示词，把你的验收标准单独抄成一个清单，跑完输出后逐条打勾。

打不了勾的那条，就是下一次要改的地方。**这个动作比"再让 AI 优化一下"有效十倍**——因为你现在知道该改哪儿了。

</div>

## 标准三：可交接

**把这条提示词发给同事，他不需要问你任何问题就能用。**

这一条最容易被忽略，但它是"个人技巧"和"团队资产"的分界线。不可交接的提示词有几个典型特征：

- 里面有只有你懂的简称："按老规矩整理""参考上次那版"
- 依赖你脑子里的上下文：没写清楚这份东西给谁看
- 需要你手动改好几处才能用，但没标出来是哪几处

修法很简单：**把要替换的地方用方括号标出来**，像本书[模板库](../reference/prompts)那样：

```text
你是一位【角色】。请【任务】。
背景：【这次的项目 / 客户 / 用途】
```

一眼能看出哪几处要改，这条提示词才算交接完了。

## 三条标准怎么一起用

按顺序：**先可验收，再可复现，最后可交接。**

1. 先写出验收标准——不知道什么叫对，后面都是白调。
2. 跑五次，对着验收标准打勾，不合格的地方回去改提示词。
3. 稳定之后，把要替换的地方标出来，加两句使用说明，发出去。

::: warning 别在第一步就追求完美
第一版写个七成就去跑。**提示词是调出来的，不是想出来的**——你想不出来的问题，跑一次全冒出来了。调的方法在 [08 章](./08-iterate)。
:::
